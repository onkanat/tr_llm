## 2. Yapılan Kod Değişiklikleri

### A) `scripts/train_step_demo.py`
`KristalLM.forward` metoduna `ignore_index: Optional[int] = None` parametresi eklendi:
```python
ce_kwargs = {} if ignore_index is None else {"ignore_index": ignore_index}
loss = nn.functional.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1), **ce_kwargs)
```
Bu sayede PyTorch cross entropy fonksiyonuna hedefte `ignore_index` olan morfemleri kayıp hesabından çıkarma kabiliyeti kazandırıldı.

### B) `train.py`
Eğitim döngüsünde varsayılan olarak `<PAD>` tokeni ignore_index olarak tanımlandı:
```python
pad_ignore_index = None if "--no-pad-mask" in sys.argv else vocab.stoi.get("<PAD>", 1)
...
logits, loss = model(x, targets, sign_mask, ignore_index=pad_ignore_index)
```
`--no-pad-mask` bayrağı ile geriye dönük tam uyumluluk (regresyon serbestliği) sağlandı.

## 3. Test Paketi Doğrulaması (`tests/test_pad_loss_mask.py`)
İki yönlü matematiksel kurguyla 4 test hazırlandı ve doğrulandı:
1. `test_pad_targets_are_removed_from_loss`: PAD konumlarındaki logit değerleri manipüle edilse dahi maskeli kaybın değişmediği kanıtlandı.
2. `test_unmasked_loss_reacts_to_same_positions`: Maskesiz kurguda aynı manipülasyonun kaybı değiştirdiği gösterildi (testin ayırt edicilik kanıtı).
3. `test_ignore_index_none_matches_plain_cross_entropy`: `ignore_index=None` durumunda değişiklik öncesi davranışla birebir özdeşlik doğrulandı.
4. `test_ignore_index_equals_plain_when_no_pad_present`: Hedeflerde hiç PAD yoksa maskelemenin kayıp değerini değiştirmediği kanıtlandı.
